# Carevista Pulse Atlas

Create a premium, enterprise-grade Healthcare Analytics and Patient Monitoring Platform.

TECHNOLOGY:

React.js

TypeScript

Tailwind CSS

Recharts

Lucide React

Supabase-ready architecture

DESIGN:
Create a rich, modern hospital analytics interface using a premium white background, deep navy sidebar, teal highlights, professional typography, subtle shadows and rounded cards.

SCREEN 1: HOSPITAL OVERVIEW

Display 10 professional doctor profile cards.

Each card should include doctor photo, name, specialization, experience, patient count and availability.

Include hospital statistics: Total Doctors, Total Patients, Critical Patients and Active Monitoring.

Add search and specialization filters.

SCREEN 2: DOCTOR DETAILS
When a doctor is clicked, open their dedicated dashboard.

Doctor profile.

Specialization and experience.

Assigned patient statistics.

Patient directory with search and filters.

Patient name, age, ID, condition and health status.

SCREEN 3: PATIENT HEALTH ANALYTICS
When a patient is clicked, open an individual patient dashboard.

Include:

Patient profile and medical history.

Heart Rate (BPM).

Blood Pressure.

Oxygen Saturation (SpO2).

Body Temperature.

Respiratory Rate.

ECG waveform visualization.

Chest X-Ray image viewer with zoom.

Heart rate history graph.

Blood pressure trend graph.

Oxygen level graph.

Temperature history graph.

Medical reports and previous records.

Patient health status indicators.

INTERACTIONS:

All 10 doctor cards must be clickable.

Each doctor must have different assigned patients.

Every patient must have separate health information.

Clicking a patient must dynamically update all medical charts and details.

Include working back navigation and breadcrumbs.

Add date filters and interactive chart tooltips.

Make every navigation item functional.

IMPORTANT DESIGN REQUIREMENTS:

No basic student dashboard.

No generic template appearance.

Use a premium healthcare SaaS design.

Create a polished, spacious, professional layout.

Make it responsive.

Use realistic synthetic patient data.

Label all simulated medical readings as demo data.

Do not claim actual live sensor monitoring.

Build the complete working application, not just a static UI mockup.

Prioritize the Doctors Directory, Patient Directory and Individual Patient Analytics screens. Test the entire navigation flow and fix errors.
